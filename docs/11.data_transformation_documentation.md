# Data Transformation & Standardization

## Project 01: Government Budget Transparency & Spending Efficiency Analytics

**Financial Year:** FY 2024–25  
**Source Status:** Draft Government Reports  
**Tools:** Python, Pandas, NumPy

## 1. Objective

The objective is to standardize financial units, financial year formats, column names, data types, and analytical fields across the extracted government budget datasets.

## 2. Source Datasets

| Dataset | Original Unit | Standard Unit |
|---|---|---|
| Statement 1 | BDT Crore | BDT Crore |
| Statement 2 | BDT Thousand | BDT Crore |

## 3. Transformation Rules

### Financial Unit Conversion

1 Crore = 10,000 Thousand Taka

Statement 2:

BDT Crore = Original Amount in Thousands / 10,000

Statement 1 already uses BDT Crore and will not be converted again.

Original financial amounts and original source units must be preserved.

## 4. Standardization

- Standardize column names using lowercase and underscores.
- Trim unnecessary whitespace from text fields.
- Preserve ministry codes as text.
- Standardize the financial year as YYYY-YYYY.
- Preserve original and standardized financial units.

## 5. Derived Analytical Fields

### Budget Utilization Rate

Actual Expenditure / Budget × 100

### Budget Variance

Budget - Actual Expenditure

These metrics must use matching financial units, reporting periods, and budget definitions.

## 6. Validation

- Verify unit conversion.
- Compare operating and development expenditure with reported totals where definitions permit.
- Validate financial year.
- Check missing and invalid values.
- Preserve source data for traceability.

## 7. Output Files

- data/transformed/statement_1_standardized.csv
- data/transformed/statement_2_standardized.csv

## 8. Limitations

- Source documents are Draft reports.
- Reporting scopes may differ between statements.
- Ministry-level and overall government figures must not be combined without scope validation.
- Unverified definitions must remain documented as unresolved.
