# PostgreSQL Database Design

## Project 01: Government Budget Transparency & Spending Efficiency Analytics

**Database:** government_budget_analytics  
**DBMS:** PostgreSQL  
**Financial Year:** FY 2024–25  
**Source Status:** Draft Government Reports

## 1. Objective

Design a relational PostgreSQL database to store government budget summary and ministry-wise expenditure data with source traceability and referential integrity.

## 2. Database Schemas

| Schema | Purpose |
|---|---|
| staging | Imported source data |
| analytics | Structured analytical tables |

## 3. Tables

| Table | Type | Purpose |
|---|---|---|
| source_documents | Metadata | Source document tracking |
| dim_fiscal_year | Dimension | Financial year information |
| dim_ministry | Dimension | Ministry identification |
| fact_government_budget_summary | Fact | Government-level budget figures |
| fact_ministry_budget | Fact | Ministry-level financial figures |

## 4. Primary Keys

- source_documents.source_document_id
- dim_fiscal_year.fiscal_year_id
- dim_ministry.ministry_id
- fact_government_budget_summary.government_budget_id
- fact_ministry_budget.ministry_budget_id

## 5. Foreign Keys

- fact_government_budget_summary.fiscal_year_id references dim_fiscal_year.
- fact_government_budget_summary.source_document_id references source_documents.
- fact_ministry_budget.fiscal_year_id references dim_fiscal_year.
- fact_ministry_budget.ministry_id references dim_ministry.
- fact_ministry_budget.source_document_id references source_documents.

## 6. Data Type Decisions

- Ministry code: VARCHAR
- Ministry name: VARCHAR
- Financial year: VARCHAR
- Financial amounts: NUMERIC(20,4)
- Percentages: NUMERIC(12,4)
- Source URLs: TEXT
- Creation timestamp: TIMESTAMP

## 7. Unit Standardization

All financial values stored in analytical fact tables use BDT Crore.

Original source units:

- Statement 1: BDT Crore
- Statement 2: BDT Thousand

Original source information is retained in source document metadata and source datasets.

## 8. Important Design Decisions

1. Government-level and ministry-level data are stored separately.
2. Source document metadata is maintained.
3. Primary and foreign keys support data integrity.
4. Ministry codes are stored as text.
5. Financial values use NUMERIC data types.
6. Ministry/year uniqueness constraints will be determined after validating dataset granularity.
7. Source reports retain their Draft status.

## 9. Limitations

The database structure is an initial relational design based on the currently identified report fields. Final column mapping must be verified against the actual extracted CSV files.
